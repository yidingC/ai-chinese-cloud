# 题型任务书（第三批）

- **本批 4 个**：拼音—汉字—含义匹配、分类归组、拼字/组词、找错误/改错
- 这 4 个都**不需要音频、不需要语音识别、不需要图片**，可以像一期那样并行开工，一人一个页面
- 做完这批，9.17 那 14 类里就只剩 1 个等音频的 ＋ 3 个要语音的（见第八节）
- 一期、二期的约定继续有效，见 `docs/题型任务书.md` 和 `docs/题型任务书-二期.md`，本文不重复
- 只写任务书，不动代码

## 一、和一期二期一样的部分

照搬，不另立规矩：

- 文件名固定 `interaction-<type>.html`，样式 `interaction-<type>.css`，脚本 `interaction-<type>.js`
- 体验模式：`interaction-category.html?type=category`（不记分）；课堂模式：`?type=category&mode=class&slot=1`
- 六个部件：顶栏、题型角标、进度、作答区、双语底部提示条、完成弹窗
- 状态机：待作答 → 已选择 → 已提交 → 正确 / 错误
- 完成时调用 `AICloudActivity.finish({ correct, seconds })`
- 完成弹窗两个按钮：「换一个题型」→ `classroom.html?activities=1`，「返回课堂」→ `classroom.html`
- 不要修改公共文件，`shared/activity-types.js` 里只改自己那条的 `ready`

**本批分两类手感**，写的时候注意别弄混：

| 手感 | 题型 | 判分方式 |
| --- | --- | --- |
| 闯关式（允许原地重试） | 拼音—汉字—含义匹配 | `correct` 恒为 `true`，看完成率和用时 |
| 判分式（每题只判一次） | 分类归组、拼字/组词、找错误/改错 | 如实传 `correct` |

## 三、拼音—汉字—含义匹配 · interaction-pinyin-match.html

### 为什么不做三列连线

三列（拼音 / 汉字 / 含义）在 390px 手机上每列只剩 100 多像素，"zǎo shang" 这种拼音根本放不下，画出来的线也会糊成一团。
所以改成**一屏一组、音 → 形 → 义 两段选择**：拼音作为起点给出，学生先选汉字，再选意思。手机上不挤，而且顺序正好是"听到音 → 想到字 → 明白义"。

### 3.1 页面上有什么

- 题面：一行提示「把拼音、汉字和意思配起来」
- 题型角标：拼音—汉字—含义匹配
- 进度：第 1 / 1 题 ＋ 组进度「第 2 / 3 组」
- 作答区：
  - 顶部：这一组的拼音（大字居中）
  - 第一段：3 个汉字候选
  - 第二段：选完汉字后才出现，3 个含义候选（印尼语）
  - 已完成区：下面用小字一行行固定已经配好的「拼音 — 汉字 — 意思」
- 底部提示条：先看拼音，选出对应的汉字，再选它的意思。 / Lihat pinyin, pilih hanzi-nya, lalu pilih artinya.
- 完成弹窗

### 3.2 操作逻辑与状态

1. 进入：待作答，显示第 1 组的拼音和汉字候选，**含义候选先不显示**
2. 点一个汉字
   - 对：汉字锁定并标绿，含义候选出现 → 已选择
   - 错：汉字标红、轻微抖动，保持可点，提示「再想想，这个音对应哪个字？」
3. 点一个含义
   - 对：这一组完成，三个信息固定到已完成区，进度 +1，0.4 秒后自动进入下一组
   - 错：含义标红、轻微抖动，保持可点
4. 三组全部完成：锁定，0.6 秒后自动弹完成弹窗
5. 点弹窗按钮：完成，调用 `finish()`

### 3.3 判定与反馈

- 每组要汉字和含义都选对才算完成；选错不换组，原地重试，不限次数
- 因为允许重试，**`correct` 恒为 `true`**（和连线、翻牌一致），这个题型看的是完成率和用时
- 选错：标红 ＋ 抖动 ＋ 一行提示，不显示正确答案
- 全部完成：弹窗写「三组全部配好！」＋ 三组对照表作为知识点
- `finish({ correct: true, seconds })`

### 3.4 模拟内容示例

| 组 | 拼音 | 汉字 | 意思 |
| --- | --- | --- | --- |
| 1 | shū | 书 | buku |
| 2 | bǐ | 笔 | pena |
| 3 | běnzi | 本子 | buku tulis |

- 第 1 组的汉字候选：书 · 笔 · 本（含义候选：buku · pena · buku tulis）
- 弹窗知识点：shū 是第一声，读得又平又高；本子 běnzi 的「子」读轻声。

## 四、分类归组 · interaction-category.html

### 4.1 页面上有什么

- 题面：一行提示「把下面的词放到对应的类别里」
- 题型角标：分类归组
- 进度：第 1 / 1 题 ＋「已归类 0 / 6」
- 作答区：
  - 上面：待归类的词，chip 样式横排、可以换行
  - 下面：2–3 个类别框，每个框有类别名和已经放进去的词
  - 词块上的字：作答中只有中文 ＋ 拼音；提交后补上印尼语意思（中文 ＋ 拼音 · 印尼语）
  - 提交按钮：还有词没归类时不可点
  - 重置按钮
- 底部提示条：先点一个词，再点它该去的类别。 / Ketuk satu kata, lalu ketuk kategorinya.
- 完成弹窗

### 4.2 操作逻辑与状态

1. 进入：待作答，所有词都在上方待归类区，类别框是空的
2. 点一个词：高亮选中，同时只能选一个 → 已选择
3. 点一个类别框：把选中的词放进去，词的 chip 从待归类区移到类别框里
4. 点类别框里已经放好的词：把它拿回待归类区，可以重新归（提交之前都能改）
5. 所有词都归类完：提交按钮可点
6. 点提交：全部锁定
7. 提交后：放对的标绿；放错的标红并**移回待归类区**，旁边标注它该去的类别
8. 点弹窗按钮：完成，调用 `finish()`

**不做拖拽**，和一期排序题一致：手机端只做点选。

### 4.3 判定与反馈

- 一个词只有一个正确类别；所有词都放对才算本题对
- 全对：绿色「答对了！」＋「6 个词全部分类正确。」＋ 一行解析
- 有错：红色「再想想」＋ 错的词标红 ＋「饺子应该放在"吃"里」＋ 解析
- 每题只判一次，不提供重试（分类有唯一答案）
- `finish({ correct, seconds })`

### 4.4 模拟内容示例

- 类别一：吃
- 类别二：喝
- 待归类的词：米饭 · 水 · 面包 · 茶 · 饺子 · 果汁
- 正确答案：吃 → 米饭 / 面包 / 饺子；喝 → 水 / 茶 / 果汁
- 解析：「吃」后面接要嚼的食物，「喝」后面接液体。饺子是食物，果汁是饮料。

## 五、拼字/组词 · interaction-word-build.html

### 5.1 页面上有什么

- 题面：一行提示「拼出这个词」＋ 印尼语意思 ＋ 一个 emoji 提示
- 题型角标：拼字/组词
- 进度：第 1 / 1 题
- 作答区：
  - 作答槽：和答案字数相同的空格（答案 2 个字就是 2 个槽）
  - 字块区：6–8 个打乱的汉字块，其中包含正确字和干扰字
  - 提交按钮：槽没填满时不可点
  - 重置按钮
- 底部提示条：点字块填进空格，点空格里的字可以拿回来。 / Ketuk kotak hanzi untuk mengisi, ketuk lagi untuk mengembalikan.
- 完成弹窗

### 5.2 操作逻辑与状态

1. 进入：待作答，槽位全空，字块打乱
2. 点一个字块：这个字填进最左边的空槽，该字块变灰、不可再点（一个字块只能用一次）
3. 点槽里的字：退回字块区，对应字块恢复可点
4. 槽全填满 → 已选择，提交可点
5. 点提交：锁定，逐槽判定
6. 提交后：对的槽描绿；错的槽描红，并在下面显示该位置正确的字
7. 点弹窗按钮：完成，调用 `finish()`

### 5.3 判定与反馈

- 逐字比对，所有槽都对才算本题对
- **字块里会有重复字**（答案本身可能是「妈妈」「爸爸」这种），判定按位置比，不能按文字去重
- 全对：绿色「答对了！」＋「妈妈 māma」＋ 一行解析
- 有错：红色「再想想」＋「正确答案：妈妈」＋ 解析
- 每题只判一次
- `finish({ correct, seconds })`

### 5.4 模拟内容示例

- 提示：👩 ＋ "ibu"
- 作答槽：2 个
- 字块：妈 · 妈 · 爸 · 姐 · 哥 · 弟
- 正确答案：妈妈
- 解析：「妈妈」两个字一样，读 māma；「爸爸」是 bàba，第一个字不一样。

### 5.5 注意

- emoji 提示沿用二期的可替换槽位写法（`icon` / `image` / `imageAlt`），本批不放真图
- 字块数量建议 6–8 个，干扰字要**同类**（比如「妈」配「爸、姐、哥」），不然一眼就排除掉了

## 六、找错误/改错 · interaction-correction.html

### 6.1 页面上有什么

- 题面：一行提示「下面这句话里有一个词用错了，点出来」
- 题型角标：找错误/改错
- 进度：第 1 / 1 题
- 作答区：
  - 一句话，拆成可点的词块（横排、可换行）
  - 提交按钮：没选时不可点
  - 反馈区
- 底部提示条：点一下你觉得不对的那个词，再提交。 / Ketuk kata yang menurutmu salah, lalu kirim.
- 完成弹窗

### 6.2 操作逻辑与状态

1. 进入：待作答，词块都可点
2. 点一个词块：高亮选中，同时只能选一个，点别的就换 → 已选择
3. 点提交：所有词块锁定
4. 提交后：
   - 选对了：学生选的那个词块加「✓ 找到了」标记，下面显示「应该是：本」＋ 改好的整句
   - 选错了：学生选的词块打灰叉，真正错的词块标红，下面显示正确答案 ＋ 改好的整句
5. 点弹窗按钮：完成，调用 `finish()`

### 6.3 判定与反馈

- 一句话里**只有一个错点**（第一版不做多错点），选中它才算对
- 反馈里**一定要给出改好的整句**，这是改错题的价值
- 全对：绿色「找对了！」＋「我买一本书。」＋ 一行解析
- 有错：红色「再想想」＋ 标出真正的错点 ＋ 改好的整句 ＋ 解析
- 每题只判一次
- `finish({ correct, seconds })`

### 6.4 模拟内容示例

- 句子：我 买 一 张 书 。
- 错的词：张
- 正确说法：我买一本书。
- 解析：「书」要用量词「本」——一本；「张」用来数纸、桌子、床。

### 6.5 第一版的范围

只做「用错的词」这一种错误类型。声调、语序、字形这些后面可以在同一页面里加变体（页面上加一排切换 chip，像一期选择题的单选/多选那样），本批先不做。

## 八、做完这批之后还剩什么

对照 9.17 那张 14 类的表：

| 剩余题型 | 状态 | 卡在哪 |
| --- | --- | --- |
| 听音选图/选词 | 暂缓 | 只差真实录音，不需要识别；音频素材到位就能做，成本很低 |
| 跟读模仿 | 未开工 | 要录音 ＋ 语音识别打分 |
| 看图说话 | 未开工 | 要录音 ＋ 语音识别打分 ＋ 图片 |
| 开放问答 | 未开工 | 要语音识别或文本判定，最难 |

也就是说，**这批做完，14 类里就剩「等音频的 1 个 ＋ 要语音的 3 个」**。后 3 个建议单独一批，先定技术方案（浏览器 MediaRecorder 能录音，但"打分"要么接外部服务、要么做本地规则），方案没定之前不要开工，容易返工。
