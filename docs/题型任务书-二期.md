## 二、内容素材约定（emoji 优先，可随时换真图）

### 1. 数据字段

每个需要"图"的地方，数据里同时留两个字段：

```js
{
  id: "cat",
  icon: "🐱",              // 现在用：emoji
  image: "",               // 以后用：填了图就优先渲染图
  imageAlt: "一只猫"        // 无障碍文字，两种情况都用
}
```

### 2. 渲染规则

统一的一个正方形槽位：

- `image` 有值 → 渲染 `<img src="...">`，`alt` 用 `imageAlt`
- `image` 为空 → 渲染 emoji，外面套 `role="img"` ＋ `aria-label="imageAlt 的值"`

**换图时只改数据，不改页面结构和样式。**

### 3. 槽位尺寸（现在定死，换图后布局不变）

| 场景 | 尺寸 | emoji 字号 |
| --- | --- | --- |
| 看图单选的大图 | 正方形，宽度撑满卡片、最大 240×240 | 88px |
| 连线的左侧图 | 正方形 96×96 | 40px |
| 情景选择的场景图 | 正方形 160×160 | 64px |
| 对话补全的场景提示（可选） | 正方形 72×72 | 32px |

emoji 一律居中、行高 1，槽位底色用浅灰或浅色圆角块，让它在没有真图时看起来也是"有意为之"，不像缺图。

### 4. emoji 挑选注意

- 用**单个基础 emoji**，不要用组合 emoji（👨‍👩‍👧 这种带零宽连接符的）和带肤色修饰的
- 选各系统渲染差别小的常见 emoji（🐱 🏫 ✏️ 这类）
- 同一题里的 emoji 风格尽量一致，不要一半写实一半抽象

### 5. 以后换成真图的步骤

把图片放进 `public/shared/demo-materials/`，在数据里把 `image` 填成 `/shared/demo-materials/xxx.png` 即可——页面代码不用动。图片规格届时按 480×480、单张 ≤100KB、图里不要带汉字。

### 6. 本批需要发起人先做的两件事

1. 在 `shared/activity-types.js` 里加 4 条空壳记录（`ready: false`），题型标识和文件名按下面第三节的对照表
2. 在 `vite.config.ts` 的 `build.rollupOptions.input` 里补上这 4 个页面（一期那 4 个已经在里面了）

## 四、看图单选 · interaction-picture.html

### 4.1 页面上有什么

- 题面：一行问题（中文），下面一行印尼语小字；选项：中文大字 ＋ 拼音小字
- 题型角标：看图单选
- 进度：第 1 / 1 题
- 作答区：上面一个正方形图槽（emoji 或真图），下面 2–4 个文字选项，纵排
- 提交按钮：没选时不可点
- 反馈区：提交后出现在选项下方
- 底部提示条：看图片，选出正确的词。 / Lihat gambar, pilih kata yang tepat.
- 完成弹窗

### 4.2 操作逻辑与状态

1. 进入：待作答，选项顺序打乱，提交不可点
2. 点选项：高亮选中，可以改选 → 已选择，提交可点
3. 点提交：选项锁定，图槽下方出现答案文字和拼音
4. 提交后：正确项描绿，选错的项描红
5. 点弹窗按钮：完成，调用 `finish()`

### 4.3 判定与反馈

- 单选，选中的那一项对才算对
- 全对：绿色「答对了！」＋「图上是 猫 māo」＋ 一行解析
- 有错：红色「再想想」＋「正确答案：B 猫 māo」＋ 同一行解析
- 每题只判一次，不提供重试
- `finish({ correct, seconds })`

### 4.4 模拟内容示例

- 图槽：🐱（以后换 `picture-animals-cat.png`）
- 题干：这是什么？
- 选项：A 猫 · B 狗 · C 鸟 · D 鱼
- 正确答案：A 猫
- 解析：「猫」是家里常见的小动物，māo；「狗」是 gǒu。

### 4.5 用到的 emoji

🐱 猫 · 🐶 狗 · 🐦 鸟 · 🐟 鱼（可再加 🐴 马、🐑 羊）

## 五、图片—词语连线 · interaction-picture-match.html

### 5.1 页面上有什么

- 题面：一行提示「把图片和词语配成对」
- 题型角标：图片—词语连线
- 进度：第 1 / 1 题 ＋ 组进度「0 / 4 组」
- 作答区：左边 3–4 个图槽（纵排，96×96 正方形、emoji 40px），右边 3–4 个词（纵排，顺序打乱，大字词语＋小字拼音）
- 底部提示条：先点左边的图，再点右边的词。 / Ketuk gambar di kiri, lalu kata di kanan.
- 完成弹窗

**本题是纯点选配对、不画线**（产品决定：图片和词语之间不需要连线层，也省掉了画线坐标随窗口变化的维护），
**不设提交按钮、不设重置按钮**（刷新即从头开始）。和 `match.html` 是同一套点选判定：配对成功即时锁定，全部配对自动完成。

### 5.2 操作逻辑与状态

1. 进入：待作答，已配对 0 / 4 组
2. 点左边的图：高亮，进入已选择；再点右侧的词做判定（同侧点击＝选中转移，再点自己＝取消选中）
3. 配对正确：两边去掉高亮、变绿并打上右上角 ✓、锁定不可再点，组进度 +1
4. 配对错误：两边红框抖动约 0.7 秒后复原，允许重连（抖动期间防连点）
5. 已经配好的项不能重复点击
6. 全部配对：所有项锁定，0.6 秒后自动弹完成弹窗
7. 点弹窗按钮：完成，调用 `finish()`

### 5.3 判定与反馈

- 逐对判定，配错即时反馈，不累计错误次数
- 全部配对即本题正确；因为允许重连，`correct` 恒为 `true`
- 配对成功/失败有无障碍播报（如「配对成功：学校，还剩 3 组」）
- 完成弹窗里写「4 组全部配对成功！」，另给一行知识点
- `finish({ correct: true, seconds })`

### 5.4 模拟内容示例

- 左边 4 个图槽：🏫 🏥 🏪 🌳
- 右边 4 个词（打乱）：公园 · 学校 · 商店 · 医院
- 正确配对：🏫 学校 / 🏥 医院 / 🏪 商店 / 🌳 公园
- 弹窗知识点：学校 xué xiào · 医院 yī yuàn · 商店 shāng diàn · 公园 gōng yuán

### 5.5 用到的 emoji

🏫 学校 · 🏥 医院 · 🏪 商店 · 🌳 公园

## 六、情景选择 · interaction-situation.html

### 6.1 页面上有什么

- 题面：场景说明（中文）＋ 印尼语对照，例如「你想借同学的笔」
- 题型角标：情景选择
- 进度：第 1 / 1 题
- 作答区：一个场景图槽（emoji 或真图）＋ 3 个说法选项，纵排
- 提交按钮：没选时不可点
- 反馈区：提交后出现，除了对错还要说明为什么
- 底部提示条：想一想，哪种说法最得体。 / Pikirkan, ucapan mana yang paling sopan.
- 完成弹窗

### 6.2 操作逻辑与状态

1. 进入：待作答，选项顺序打乱
2. 点选项：高亮，可以改选 → 已选择
3. 点提交：选项锁定
4. 提交后：正确项描绿；如果选错了，把得体说法标出来
5. 点弹窗按钮：完成，调用 `finish()`

### 6.3 判定与反馈

- 只有一句在该场景里得体，选它才算对
- 全对：绿色「答对了！」＋「这个场合这样说最合适。」＋ 一行解析
- 有错：红色「再想想」＋「更合适的说法：B 请问，我可以借你的笔吗？」＋ 解析
- 解析要写清楚**为什么另外两句不合适**（太生硬 / 场合不对 / 答非所问），这是本题型和看图单选的区别
- `finish({ correct, seconds })`

### 6.4 模拟内容示例

- 场景图槽：✏️
- 场景：你想借同学的笔。
- 选项：
  - A 喂，给我笔！
  - B 请问，我可以借你的笔吗？
  - C 笔。
- 正确答案：B
- 解析：向别人借东西要用「请问……可以吗」；A 太生硬，C 话没说完。

### 6.5 用到的 emoji

✏️ 借笔 · ⏰ 迟到道歉 · 🙋 请人帮忙（本批先做 1–2 个场景即可）

## 七、对话补全 · interaction-dialogue.html

### 7.1 页面上有什么

- 题面：一行提示「选出合适的下一句」
- 题型角标：对话补全
- 进度：第 1 / 1 题
- 作答区：对话气泡——对方的话在左边（浅色气泡，下面一行印尼语小字），自己的话在右边（主色气泡，先留空），下面是 3 个候选句
- 提交按钮：没选时不可点
- 反馈区：提交后出现
- 底部提示条：看上一句说了什么，再选下一句。 / Lihat kalimat sebelumnya, lalu pilih lanjutannya.
- 完成弹窗

### 7.2 操作逻辑与状态

1. 进入：待作答，右边气泡是空的，写着「？」占位
2. 点候选句：高亮 → 已选择
3. 点提交：候选区锁定，把选中的句子**填进右边气泡**（这一步很重要，能看出对话是否通顺）
4. 提交后：对则气泡保持主色；错则气泡变红，并在下面显示正确那句
5. 点弹窗按钮：完成，调用 `finish()`

### 7.3 判定与反馈

- 只有一句能接上下文，选它才算对
- 全对：绿色「答对了！」＋ 一行解析
- 有错：红色「再想想」＋「正确的下一句：在二楼，往左走。」＋ 解析
- 解析要指出上下文线索（上一句问的是「在哪儿」，所以下一句要回答位置）
- `finish({ correct, seconds })`

### 7.4 模拟内容示例

- 对方（左）：请问，洗手间在哪儿？
- 自己（右）：（空）
- 候选句：
  - A 在二楼，往左走。
  - B 我叫小明。
  - C 今天很热。
- 正确答案：A
- 解析：上一句问的是「在哪儿」，所以要回答位置；B 是在自我介绍，C 是在说天气，都接不上。

### 7.5 用到的 emoji

可选，场景提示用 🚻 之类的小槽位；本批可以先不做图槽，只留对话气泡。

## 八、本批暂缓：听音选图/选词

**先不做，原因**：需要真实录音，音频素材还没着落。等音频方案定了再单独开工。

留个记录，方便到时候接着做：

- 页面上要有：一个大播放按钮（🔊）＋ 3–4 个选项；**不自动播放**（浏览器会拦），学生点了才播；可以反复播放、不影响判分
- 提交后反馈里才写出音频对应的文字和拼音；答题过程中页面上任何位置都不能出现答案文字
- 模拟内容：音频读「三 sān」，选项 三 / 四 / 山 / 伞，正确答案「三」；解析讲第一声和第四声的区别
- 音频格式沿用仓库现有文件的规格：WAV、单声道、22050 Hz、16 bit、每条 1–3 秒（约 45 KB/秒）
- 提醒：`public/shared/demo-materials/greeting-review.wav` 是**占位音不是人声**（527 Hz 恒定正弦波，1.68 秒），不能当真读音用；播放逻辑可以拿它先跑通
- 录入清单：三 sān / 四 sì / 山 shān / 伞 sǎn

建议这题**先不加进** `shared/activity-types.js`，避免题型清单里挂着一个做不了的题型；等音频到位再一起补。

## 九、二期补充的验收项

一期任务书第六节的验收清单原样适用，另外加上这几条：

- [ ] 图槽在没有 `image` 时渲染 emoji，居中、尺寸符合第二节的表格，看起来像有意设计而不是缺图
- [ ] 把某个 `image` 临时填成一张真图后，槽位尺寸不变、布局不塌（验证以后能平滑换图）
- [ ] 每个图槽都有无障碍文字：emoji 用 `role="img"` ＋ `aria-label`，真图用 `alt`
- [ ] 用的都是单个基础 emoji，没有组合 emoji 和肤色修饰
- [ ] 连线的线在窗口尺寸变化后位置仍然正确
- [ ] 页面里没有硬编码本地绝对路径
