# 题型任务书 · 快速选择 / 句子排序 / 补全句子 / 课堂投票

- 适用范围：`interaction-choice.html`、`interaction-order.html`、`interaction-fill.html`、`interaction-poll.html`
- 分工：四个页面各开一个对话认领，一人一个，互不影响
- 本文件只描述**页面上有什么、操作逻辑是什么**；公共地基（题型清单、记账、跳转、右下角题型体验入口）由另一个线程负责，不要在各自页面里重复实现
- 公共约定以 README 的「学生端题型扩展约定（第一批）」为准；两边不一致时以 README 为准

## 一、四个页面共用的约定

### 1. 题型与文件对照

| 题型 | 题型标识 `type` | 页面文件 | 自己新增的样式文件 |
| --- | --- | --- | --- |
| 快速选择（一个词 ＋ 四个大图） | `choice` | `interaction-choice.html` | `interaction-choice.css` |
| 排序 | `order` | `interaction-order.html` | `interaction-order.css` |
| 填空 | `fill` | `interaction-fill.html` | `interaction-fill.css` |
| 投票 | `poll` | `interaction-poll.html` | `interaction-poll.css` |

文件名固定，不要改。

### 2. 两种进入方式

| | 体验模式 | 课堂模式 |
| --- | --- | --- |
| 网址 | `interaction-choice.html?type=choice` | `interaction-choice.html?slot=1&type=choice&mode=class` |
| 怎么进来 | 学生端右下角演示面板 →「题型体验 / 题型速览」，点清单里的一行 | 课堂页的三张关卡卡（老师布置的课堂互动） |
| 记不记分 | **不记**：不写课堂进度，不影响课堂页的关卡 | **记**：写入课堂进度；三关都完成后回课堂页弹一次大恭喜 |
| 完成弹窗 | 公共模具弹窗：【返回课堂】＋【再练一次】 | 同一套公共模具弹窗（先记进度）；点【返回课堂】回课堂页 |

页面里判断当前模式：

```js
const ctx = AICloudActivity.context(); // { mode, slot, type, activity, ... }
if (ctx.mode === "class") { /* 课堂模式 */ } else { /* 体验模式，网址里没有 mode=class */ }
```

### 3. 外壳照抄现有页面

复用这些已有样式类，页面之间看起来要是一套：`app-shell`、`status-bar`、`page-header`、`modal-overlay`、`completion-modal`、`primary-button`、`secondary-button`、`btn-stacked` / `btn-id`（双语按钮）。
需要额外样式时只新增自己的 `interaction-xxx.css`，**不要动 `styles.css`**（多人并行会冲突）。

### 4. 页面上必须有的部件（2026-09-20 现状）

| 部件 | 说明 |
| --- | --- |
| 假手机状态栏 `status-bar` | 顶部时间 ＋ 信号，演示用，保留 |
| 顶栏 `page-header` | 返回按钮（体验模式回首页，课堂模式回课堂页）＋ 题型标题（2026-09-29 起不再放印尼语副标题） |
| 作答区 | 各题型不同，见下面各节 |
| 提交键 | 双语两行「提交 / Kirim」；提交后原地变灰、变「已提交 / Terkirim」 |
| 反馈区 | 页面只说事实：对＝绿 ✓，错＝红框 ＋ 正确答案行（不写中文解析） |
| 完成弹窗 | 公共模具（`shared/feedback-modal.js`）：徽标 ＋ 双语标题（情绪句）＋【返回课堂 / Kembali ke kelas】【再练一次 / Coba lagi】 |

> **已删除，不要再加回来**（2026-09 全站精简）：题型角标、进度「第 1 / 1 题」、底部双语提示条。右下角的演示控件（🎮 题型体验、演示面板、假手机状态栏）保留，别删。

### 5. 四个题型共用的状态机

| 状态 | 什么时候进入 | 界面表现 |
| --- | --- | --- |
| 待作答 | 刚进页面 | 提交按钮不可点 |
| 已选择 | 点了选项 / 输入了内容 / 调过顺序 | 提交按钮可点 |
| 已提交 | 点了提交（每题只提交一次） | 作答区锁定，不能再改 |
| 正确 | 判定通过 | 绿 ✓（有的页配一句短标题，如「答对了！」）；不写中文解析 |
| 错误 | 判定不通过 | 红框 ＋ 正确答案行；不写中文解析 |

### 6. 完成时统一调用

```js
AICloudActivity.finish({ correct: true, seconds: 12 });
```

- `correct`：本题对错（投票恒为 `true`）
- `seconds`：从进入页面到提交的秒数
- 课堂模式会自动记进度；弹窗两种模式都弹（公共模具 `shared/feedback-modal.js`，见 `docs/视觉打磨规范-v0.3.md` 第五、十三节），页面**不要自己写跳转**
- 体验模式不记账；两种模式的完成弹窗按钮统一为【返回课堂】＋【再练一次】（都带印尼语副行）
- 弹窗标题的情绪句从 `shared/feedback-copy.js` 句池抽（传 `tier`：correct / correctFirstTry / wrong），页面不自己编夸奖句

### 7. 做完之后的收尾

把 `shared/activity-types.js` 里自己那条的 `ready` 从 `false` 改成 `true`，题型清单里它那一行就会从灰底「待认领」变成可点的「可体验」。

### 8. 不要修改的公共文件

`styles.css`、`app.js`、`README.md`、`shared/activity-bridge.js`、`shared/activity-page.js`、`shared/feedback-modal.js`、`shared/feedback-copy.js`、`shared/activity-fab.js`、`classroom.html`、`index.html`、`match.html`、`memory.html`。
`shared/activity-types.js` 只改自己那条的 `ready`，别的不动。

### 9. 按钮文案与双语副行（2026-09-20 起全站统一）

学生要按的按钮一律"中文主词 ＋ 一行印尼语小字"，新页面照抄这张表：

| 场景 | 中文主词 | 印尼语副行 |
| --- | --- | --- |
| 提交键 | 提交 | Kirim |
| 清空键 | 重置 | Ulangi |
| 提交后灰态（同一颗按钮原地变字、变灰） | 已提交 | Terkirim |
| 弹窗主按钮 | 返回课堂 | Kembali ke kelas |
| 弹窗次按钮 | 再练一次 | Coba lagi |

- 写法：按钮加 `btn-stacked`，里面放两个 span（主词 ＋ `.btn-id`）；JS 切三态只改这两个 span，**不要整体替换按钮的 `textContent`**（会把印尼语那行弄丢）；
- 弹窗按钮不用自己写，公共层按文案自动补副行；
- 副行字号全站只有 11px 一个值；详见 `docs/视觉打磨规范-v0.3.md` 第十三节（含写法与红线）。

## 二、快速选择 · interaction-choice.html

### 2.1 页面上有什么

- 题面：一个词（中文大字）＋ 拼音，居中
- 作答区：四个大图块（emoji）排成 2×2，点一张选中；图上不带文字标签
- 提交键：双语两行「提交 / Kirim」；提交后原地变灰、变「已提交 / Terkirim」
- 反馈区：提交后在选项下方出现（对＝绿 ✓；错＝红框 ＋ 正确答案）
- 完成弹窗：公共模具（情绪句 ＋【返回课堂】【再练一次】）

### 2.2 操作逻辑与状态

1. 进入页面：待作答，选项顺序每次打乱，提交键不可点
2. 点图块：选中（紫描边）；再点一次取消；改选另一张时，之前那张自动取消 → 已选择 / 待作答
3. 点提交：进入已提交，所有选项锁定，不能再点
4. **选完再提交**，不要点一个判一个
5. 提交后：正确项描绿（不管有没有选它），选错的项描红；反馈区给正确项（图 ＋ 印尼语意思），不写中文解析
6. 点弹窗按钮：【返回课堂】回课堂页 /【再练一次】就地重开；完成时调用 `finish()`

### 2.3 判定与反馈

- 只有单选：选中的那张就是正确答案才算对
- 全对：绿 ✓ ＋「答对了！」＋ 正确项（图 ＋ 印尼语意思）
- 有错：红框 ＋ 正确项（图 ＋ 印尼语意思）；不写中文解析
- 每题只判一次，不提供重试
- `finish({ correct: 本题对错, seconds: 用时秒数 })`

### 2.4 模拟内容示例

- 题干：一杯茶（Yì bēi chá）
- 选项：🍚 一碗米饭 / 👕 一件衣服 / 📚 一本书 / 🍵 一杯茶（四张图，顺序每次打乱）
- 正确答案：🍵 一杯茶
- 上屏的内容只有「图 ＋ 印尼语意思」，如「🍵 Secangkir teh」
- 说明（不上屏，内容侧留档）：「喝」后面接能喝的东西，茶、水、咖啡都可以；米饭要用「吃」。

## 三、句子排序 · interaction-order.html

### 3.1 页面上有什么

- 题面：场景提示或印尼语意思（中文 ＋ 印尼语）；**不要显示正确句子**
- 作答区（上下两块）：
  - **答案行**：一条横向下划线，选中的词块从左到右排在这条线上；一个词都没选时显示浅提示「点下面的词开始组句」
  - **词库**：打乱顺序的词块（汉字 ＋ 小号拼音），每块是一个按钮；词块被选走后原位留一个浅灰占位框，其余词块不移动
- 按钮：左侧「重置 / Ulangi」，右侧「提交 / Kirim」（答案行里至少 1 个词才可点）；提交后提交键原地变灰、变「已提交 / Terkirim」
- 反馈区：对＝不弹结果框（答案行自己描绿）；错＝红框里给正确顺序的句子
- 完成弹窗：公共模具（情绪句 ＋【返回课堂】【再练一次】）

### 3.2 操作逻辑与状态

1. 进入页面：待作答，词块已经打乱（要保证打乱后不等于正确顺序）
2. 点词库里的词块：词块进入答案行末尾，词库原位留浅灰占位框 → 已调整
3. 点答案行里的词块：退回词库原位置，后面的词依次前移
4. 手机端**不做拖拽**，学生端只用「点选」（拖拽是后台教师端才有的）
5. 每次选入/放回用 `aria-live` 播报（例如「已选入「我」，已选 2 个词」），键盘用 Tab ＋ 回车就能操作
6. 点清空：所有词回到词库，回到待作答
7. 点提交：逐位判定，进入已提交，词块和按钮全部锁定
8. 点弹窗按钮：完成，调用 `finish()`

### 3.3 判定与反馈

- 逐位比对，每个位置都对才算本题对
- 出现重复词（「的」「了」这种）时**按位置判**，不能按文字去重
- 全对：不给结果框，排好的句子那行描绿
- 有错：红框里按顺序列出正确句子；不写中文解析
- 每题只判一次
- `finish({ correct: 本题对错, seconds: 用时秒数 })`

### 3.4 模拟内容示例

- 题面：把词语排成一句话。 / Susun kata menjadi kalimat.
- 词库（打乱后）：苹果 · 我 · 一个 · 想 · 买
- 正确顺序：我 → 想 → 买 → 一个 → 苹果
- 说明（不上屏，内容侧留档）：中文语序是「谁 ＋ 想做什么 ＋ 做什么」；「一个」放在名词「苹果」前面。

## 四、补全句子 · interaction-fill.html

### 4.1 页面上有什么

- 题面：一句完整的话，中间留 1–3 个空
- 作答区：句子（空是下划线槽位）＋ 下面一排可点的词块（含干扰词）
- 提交键：双语两行「提交 / Kirim」；提交后原地变灰、变「已提交 / Terkirim」；左边还有「重置 / Ulangi」
- 反馈区：对＝绿 ✓ ＋「答对了！」＋ 完整原句（＋印尼语）；错＝错的空标红，结果框给完整原句；不写中文解析
- 完成弹窗：公共模具（情绪句 ＋【返回课堂】【再练一次】）

### 4.2 操作逻辑与状态

1. 进入页面：待作答，**所有空都填了**提交键才可点
2. 点词库里的词：填进最左边的空，词库原位留浅灰占位
3. 点句子里已填的词：它回词库，那个空重新空出来
4. **不做打字输入**（印尼学生打不出中文）：只点词块
5. 点提交：逐空判定，词块和空一起锁定不可再改
6. 点弹窗按钮：【返回课堂】回课堂页 /【再练一次】就地重开；完成时调用 `finish()`

### 4.3 判定与反馈

- 逐空比对：该空填的词块文字和答案一致才算对（点选式，不用做拼音 / 大小写容错）
- 所有空都对才算本题对
- 全对：绿 ✓ ＋「答对了！」＋ 完整原句（＋印尼语）
- 有错：错的空标红，结果框给完整原句；不写中文解析、不写"差几个"
- `finish({ correct: 本题对错, seconds: 用时秒数 })`

### 4.4 模拟内容示例

- 句子：我每天 ＿＿ 七点 ＿＿，然后 ＿＿ 学校。
- 词库（打乱）：早上 · 起床 · 去 · 书包 · 喝（后两个是干扰词）
- 正确答案：早上 / 起床 / 去
- 说明（不上屏，内容侧留档）：「早上」指上午早一些的时候，放在时间词的位置。

## 五、课堂投票 · interaction-poll.html

### 5.1 页面上有什么

- 题面：一行问题，可以配一张图
- 作答区：选项 2–4 个，纵向排列，单选样式（圆点）；下面是提交按钮
- 提交键：双语两行「提交 / Kirim」；提交后原地变灰、变「已提交 / Terkirim」
- 反馈区：页面不给对错也不写字；自己选的那项保持选中
- 完成弹窗：公共模具（标题＝内容回应句，如「收到啦！/ Sudah diterima!」）

### 5.2 操作逻辑与状态

1. 进入页面：待作答，提交按钮不可点
2. 点选项：切换选中（单选，改主意就点别的那个）→ 已选择
3. 点提交：进入已提交，选项锁定不可再改
4. 提交后页面不给对错也不写字，自己选的那一项保持高亮，提交键变灰「已提交 / Terkirim」
5. **不计分**：不显示对错、不显示「再想想」、不显示正确答案
6. 点弹窗按钮：完成，调用 `finish()`

### 5.3 判定与反馈

- 没有对错
- 提交后页面上只把提交键变灰（已提交 / Terkirim），不出现对错字样
- 调用 `finish({ correct: true, seconds: 用时秒数 })`，`correct` 恒为 `true`（写成 `false` 会被当成答错）
- 全班统计在公共地基那边，本页面不做

### 5.4 模拟内容示例

- 问题：下课后你最喜欢做什么？
- 选项：A 听音乐 · B 打篮球 · C 看中文动画 · D 和朋友聊天
- 提交后：听音乐那项保持选中，弹窗出「收到啦！」；页面上不写字

## 六、通用验收清单

- [ ] 顶栏返回按钮能回到该去的地方：体验模式回首页，课堂模式回课堂页
- [ ] 没有题型角标、没有「第 1 / 1 题」、没有底部提示条（2026-09 全站删了，别加回来）
- [ ] 提交后能看到对错（颜色 ＋ 图标，不能只靠颜色区分），反馈里不写中文解析
- [ ] 提交键是双语两行：提交 / Kirim → 已提交 / Terkirim（不整体替换按钮文字）
- [ ] 完成后弹窗是公共模具：【返回课堂 / Kembali ke kelas】＋【再练一次 / Coba lagi】
- [ ] 单独体验（网址里没有 `mode=class`）不写课堂进度、不影响课堂页三关
- [ ] 手机宽度（约 390px）下不横向滚动，按钮不被挤出屏幕
- [ ] 只新增了 `interaction-xxx.css`，没有修改任何公共文件
- [ ] `shared/activity-types.js` 里自己那条的 `ready` 已改成 `true`
- [ ] 全程只用键盘也能完成作答

## 七、和公共地基对齐的接口点

写完页面后由发起人对齐，四个对话按同一口径处理：

1. 没有「换一个题型」按钮了（2026-09 起）：完成弹窗只有【返回课堂】回 `classroom.html`、【再练一次】就地重开
2. 完成弹窗是自己用 `completion-modal` 写，还是由公共脚本统一弹
3. `finish()` 在课堂模式只记进度（`next` 指向 classroom.html，不再自动跳转）；两种模式都弹完成弹窗，跳转由弹窗的【返回课堂】按钮负责
4. 题型标题直接取自 `AICloudActivityTypes.get(type)` 里的字段，不要各写一份（2026-09-29 起页头不再放印尼语副标题）

## 八、公共地基对齐结论（2026-09-17，以此为准）

公共地基已经在仓库里就位（`shared/activity-types.js`、`shared/activity-bridge.js`、`shared/activity-fab.js`、`shared/activity-page.js`、`styles.css` 新增样式、README 章节）。四个页面按下面的结论对接：

1. **不做随机抽题，也不要修改 `classroom.html`。** 课堂页「今日互动」的三张卡是老师布置的内容，当前固定是快速选择、看图单选和问候时间连线（2026-09-20 起），学生端不参与抽题。`ready` 改成 `true` 的作用只有一个：让右下角「题型体验」清单里自己那一行从灰底「待认领」变成可点的「可体验」。
